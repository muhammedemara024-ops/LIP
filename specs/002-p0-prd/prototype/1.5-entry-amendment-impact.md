### P4 — PD-044 (new, Proposed): prototype format, locales, accessibility target

**Draft decision text:**
1. **Format.** The 1.5 prototype is built in **Figma**: an editable source plus a clickable prototype.
   - It holds only fictional data and no credentials (brief AC-11).
   - Who owns the Figma account, who has access, and any cost are recorded. PD-006's $100 cap covers deployment services, not this tool.
2. **Locales.** Every screen exists in **Arabic RTL (default) and English LTR**. This restates FR-130 and PD-007; nothing new.
3. **Accessibility.** **WCAG 2.2 Level AA** is the target. The owner must choose its scope:
   - **(a) Design target for the 1.5 prototype only.** This is the minimum needed to start 1.5 and adds no product requirement.
   - **(b) Also a P0 product requirement.** This is a new requirement. It needs an owner-approved PRD amendment (a new FR and SC), plus re-review of the UI task cards' tests and acceptance criteria (T011, T026, T027, T042, T045 and others), under rule 05 field 13.
4. **Branding isolation.** No change. PD-043 item 3 (Approved) already excludes the name from the engine, APIs, schemas, identifiers, package names and business logic. The one-value-per-locale mechanism stays Proposed until the owner confirms it.

**WCAG facts to carry into the decision** (to be verified against W3C sources during 1.5):
- A design file can show only design-level criteria. Examples: contrast (1.4.3, 1.4.11), target size (2.5.8, AA in 2.2), visible labels and instructions, and consistent help (3.2.6).
- Conformance of the shipped UI can be shown only on implemented screens.
- **Possible tension to resolve, not resolved here:** WCAG 2.2 SC 3.3.8 *Accessible Authentication (Minimum)* limits cognitive-function tests in sign-in. It must be checked against the approved staff PIN sign-in (FR-014, PD-010) and OTP entry. For example, OTP entry may need paste or autofill support. If adopting scope (b) conflicts with an approved decision, it goes back to the owner. It never silently changes PD-010.

**Risks and how they are handled:**
- **R1 — Rework if the final name differs.** The swap is limited to copy and assets (PD-043). It is one value per locale only if the owner confirms that mechanism.
- **R2 — Measurement fidelity.** A Figma prototype can show tap counts and walkthrough time. It cannot show real camera scanning, OTP delivery or device performance. **Owner decision:** whether 1.3 (b) "works on a cheap Android phone" and 1.4 (b) are satisfied by a Figma-on-device run, or need a later re-check on the implemented app. The thresholds stay as they are; only the evidence basis is decided.
- **R3 — Accessible authentication.** See the 3.3.8 tension under P4.
- **R4 — Approval layering.** Amending text in plan, tasks and spec artifacts approved at Gate 1, the Planning Gate and Gate 2 needs explicit owner approval naming each change. A reviewer verdict does not substitute.

**Rollback:** each change is text-only and reversible by restoring the earlier wording with a dated note. No data, schema or contract is affected.
