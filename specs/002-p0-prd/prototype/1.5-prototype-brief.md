## 4. Branding separation rules for the prototype (principle: PD-043 item 3; mechanism Proposed)

- Approved principle: the product name appears only in user-visible copy and brand assets.
- Proposed mechanism, **pending owner confirmation**: one brand value per locale (`ar`: ونيس, `en`: Wanees, or the final name later), which screens, components, flows and annotations reference instead of literal text.
- Brand text is never used in screen IDs, component names, flow names, sample API paths, sample error codes, sample IDs or data labels shown as identifiers.
- While the working name is in use, every screen shows a visible label: "اسم عمل — غير نهائي / Working name — not final".
- No upstream Crave branding is used (PD-029).

## 5. Deliverables (authorized 2026-11-13 for design only, PD-045)

- **D1 — Screen inventory.** Every P0 screen and state, each traced to its user story, its FR and the Approved decisions that apply.
- **D2 — Arabic RTL design system:**
  - tokens: colour, Arabic and Latin type, spacing, radii and elevation;
  - RTL mirroring rules;
  - digit, amount and time display rules;
  - core components with their states.
- **D3 — Clickable prototype** of every D1 screen in **Figma** (PD-044), Arabic default with English LTR variants. It lives in a non-production workspace holding fictional data only. Ownership, access and cost are recorded when the workspace is set up.
- **D4 — Annotation layer:**
  - decision-dependent markers;
  - tap counts on cashier steps;
  - the onboarding path's start and stop markers for the timed walkthrough.
- **D5 — Review record.** A dated owner approval, or a list of required changes.

**Starter screen list for D1** (derived from spec US1–US14, to be verified during D1).

**Customer:**
- Branch-QR landing and join: phone plus first name only (PD-023).
- OTP entry, resend timer and limit messages (PD-020, PD-042).
- Card view: progress, rewards, visit history with branch, and balances expiring soon with date and time in Cairo (FR-120). Program, reward and branch names fall back to the café's main content language (FR-131).
- Member code: device-bound, 60 s. Offline display only on an installed app that was opened online before on that device; the screen shows the state when that condition fails (FR-121).
- Rewards list and reward code.
- Expiring-reward indicator: an in-app indicator for issued rewards that expire within 7 days, with no external reminder (approved principle, PD-041 JG-12). Its window semantics are open (F-12).
- Purchase claim by Branch QR (US6).
- Pending paper-card migration: café name and the exact stamp count; the customer accepts or declines; it expires after 15 minutes (FR-122, PD-022, US11).
- Account: devices, consent, language, delete account (US10).
- Support contact: the platform WhatsApp number with phone fallback; support never changes balances (FR-141, PD-019).
- Recovery entry points (US14; mechanisms blocked F-03/F-04/F-06).

**Cashier:**
- Device enrollment.
- PIN login.
- Scan member code.
- Amount entry and engine preview (PD-039).
- Confirm and the uncertain-accrual state (research R-14). The baseline is fail-closed: an uncertain accrual is never re-sent (PD-038 P8). The next cashier action stays decision-dependent (OD-10, OD-15, OD-17).
- Redeem: scan the reward code, then the 120 s hold (OD-16 boundary).
- Claim-code entry (format OD-12).
- Void / undo (US5).
- Refusal and offline states.

**Owner:**
- Invite acceptance plus OTP.
- Branch and opening hours (PD-026).
- Program wizard, stamps and points (ranges F-12; points publishing OD-02).
- Publish with step-up.
- Print-ready Branch QR.
- Staff, devices and branches (US7).
- Customers (search by first name plus last 3 digits), transactions, rewards, KPIs (US8, PD-013).
- Voids and classified corrections (US5). Fresh authentication for a dashboard void is decision-dependent (OD-11). An owner award above 5 × the threshold is decision-dependent (OD-18); it is not designed as decided.
- Paper-card migration: create from the owner staff profile with fresh owner authentication, then attest that the paper card was collected or marked VOID (US11, PD-021, PD-022).
- Fraud alerts (US12). Deduplication of overlapping alert windows is decision-dependent (OD-14).
- Program changes after launch (US13).
- Subscription-stage banners and disabled actions (PD-005 A2–A4).

**Super Admin:** no screens. P0 operator tools are a CLI (`contracts/operator-api.md`); the console is P1 task 6.7.
